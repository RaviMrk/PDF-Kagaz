# Milestone 3 — Reader and "Open with" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any indexed or shared PDF opens in `/reader/[id]` within a second, scrolls and zooms smoothly, resumes at the last page, supports jump-to-page, a thumbnail strip, night/sepia/keep-screen-on, horizontal paging, password-protected files, bookmarks + outline, and share/print/open-with; the app is an "Open with"/share target for `application/pdf` (V-01 to V-10, F-06). Two Milestone 2 review residuals are fixed first.

**Architecture:** `react-native-pdf` 7.0.5 (Fabric component `RNPDFPdfView`, Android engine = AndroidPdfViewer + PdfiumAndroid) renders pages, but only ever from a local `file://` path: `pdf-native` prepares that path (the original file, or a streamed copy in `cacheDir/reader/` for `content://` sources — the original is never written). One typed wrapper (`src/components/reader/PdfView.tsx`) is the only importer of `react-native-pdf`; it is memoised so that no React re-render reaches the native view (on Fabric every prop update reloads the whole document). Reader logic lives in pure services (`src/services/reader/*`: state machine, page input, last-page saver, thumbnail loader, actions); `pdf-native` gains a separate reader-thumbnail lane (own lock, cached renderer), share/print/open-with intents, and incoming-intent handling. `VIEW` intents arrive through Expo Router (`app/+native-intent.tsx` → `/open`), `SEND` intents through a `pdf-native` event; both index the file as source `'intent'` and open the reader.

**Tech Stack:** Expo SDK 57 (`expo@~57.0.30`, RN 0.86.3, New Architecture, Gradle 9.3.1 / AGP 8.12), Expo Router 57 (typed routes, `+native-intent`, `useFocusEffect`), `react-native-pdf@7.0.5` + `react-native-blob-util@0.25.1` (+ `prop-types`), `expo-keep-awake@~57.0.2`, Expo Modules API (Kotlin: `OnNewIntent`, `Events`, `Coroutine`), Android `PdfRenderer`, `PrintManager`, `FileProvider`; expo-sqlite + drizzle-orm 0.45; Zustand 5; `@shopify/flash-list` 2.0.2; Jest (jest-expo, `expo-router/testing-library`, better-sqlite3); JUnit 4.13.2.

**Spec:** `docs/REQUIREMENTS.md` (sections 1, 3.1 F-06, 3.2 V-01–V-10, 4, 6, 7.2, 8, 9 milestone 3, 10.1, 11)

## Global Constraints

- Android only; no iOS code. minSdk 24, targetSdk 36, compileSdk 36. Dev build, New Architecture. App orientation stays `portrait` (app.json).
- TypeScript `strict: true`; `npm run typecheck`, `npm run lint`, `npm test`, `npm run format:check` pass at the end of every task.
- All user-facing strings via i18next `src/i18n/en.json` (exact copy is given per task; `mr.json`/`hi.json` stay `{}`); touch targets ≥ 48 dp; every pressable has an `accessibilityLabel`; no `allowFontScaling={false}`.
- Screens never call native code or `react-native-pdf` directly: native only through `src/services/**` (which use `pdfNative` from `src/services/native/pdfNative.ts`), `react-native-pdf` only through `src/components/reader/PdfView.tsx`. Routes only in root `app/` (never `src/app/`).
- Native module: folder `modules/pdf-native`, Kotlin package `com.pdfkagaz.pdfnative`, module name `PdfNative`, Gradle project `:pdf-native`. Every `AsyncFunction` that touches disk, a `ContentResolver` or `PdfRenderer` is a `Coroutine` that does that work inside `withContext(Dispatchers.IO)`; `startActivity`/`PrintManager.print` run on `Dispatchers.Main`. Pure Kotlin classes import nothing from `android.*` so JUnit runs on the JVM.
- Native errors are `CodedException`s with exactly these codes (no new codes in M3): `ERR_FILE_NOT_FOUND`, `ERR_PDF_ENCRYPTED`, `ERR_PDF_INVALID`, `ERR_PERMISSION_DENIED`, `ERR_FILE_EXISTS`, `ERR_INVALID_NAME`, `ERR_PASSWORD_UNSUPPORTED`, `ERR_NO_ACTIVITY`, `ERR_IO`, `ERR_VOLUME_UNAVAILABLE`. Error messages never contain names, paths or URIs.
- Row removal rule: only a confirmed `ERR_FILE_NOT_FOUND` may remove an index row. `ERR_VOLUME_UNAVAILABLE`, `ERR_IO`, `ERR_PERMISSION_DENIED` (and anything else) show a message and keep the row.
- Never overwrite or modify an original file. Reader copies of `content://` sources go to `cacheDir/reader/` via a `.part` file then rename; copies are app-cache only.
- Passwords live only in React state for the open reader: never persisted, logged, put in a route param or sent to native except as the `password` prop of the viewer.
- Privacy: no file names, paths or URIs in our logs. Timing logs may print counts and milliseconds only; `[reader] first page <ms>ms <count> pages` is allowed in release builds (Task 10 measures V-01 with it). Known limitation: `react-native-pdf` itself `Log.d`s the loaded path (library code, local logcat only, nothing leaves the device); revisit with an R8 `-assumenosideeffects` rule when minify is enabled in M6.
- No ads in the reader (spec 1). No network use anywhere in the reader.
- Install Expo/native packages with `npx expo install <pkg>` (exact versions where this plan pins them).
- Java for Gradle: `export JAVA_HOME=~/.gradle/jdks/eclipse_adoptium-17-aarch64-os_x.2/jdk-17.0.20.1+1/Contents/Home`; `export ANDROID_HOME=~/Library/Android/sdk`. `android/` is generated (gitignored): after native/config changes run `npx expo prebuild --platform android --clean`.

**Decisions this plan makes (spec leaves them open), each checked against node_modules / package sources / versioned docs on 2026-10-21:**
- **Viewer = `react-native-pdf@7.0.5` (pinned exactly), with a device gate in Task 2.** Checked: npm latest is 7.0.5 (2026-08-13); it ships a codegen Fabric component (`fabric/RNPDFPdfNativeComponent.js`, command `setNativePage`) and applies `com.facebook.react` when `newArchEnabled=true` (set in `android/gradle.properties`); Android engine `com.github.zacharee:AndroidPdfViewer:4.0.1` (pure Java, JitPack — already in the root `allprojects` repos) + `io.legere:pdfiumandroid:1.0.32`, whose `arm64-v8a`/`x86_64` `.so` files have LOAD alignment `2**14` (16 KB-ready, checked with `llvm-objdump -p`). Its `build.gradle` uses AGP-7 DSL (`lintOptions`, `packagingOptions`) — deprecated but present in AGP 8.12; Task 2's build proves it. Fallback (only if the Task 2 gate fails): stop and re-plan around a `pdf-native` `PdfRenderer` page renderer (`renderPage(fileUri, page, width)` → JPEG) shown in a FlashList with gesture-handler pinch zoom; passwords would then need PdfBox-Android decryption to a cache copy. Not chosen up front because PdfRenderer cannot open password-protected PDFs or read outlines (V-08, V-09).
- **`content://` is never handed to `react-native-pdf`.** Its Android code opens `content://` through `fromStream()`, and AndroidPdfViewer's `InputStreamSource` calls `Util.toByteArray` — the whole file in the Java heap (OOM risk for 50–100 MB, spec 4 Memory). `file://` paths go through `ParcelFileDescriptor` (pdfium reads lazily). So `pdf-native.prepareReaderFile` returns the original `file://` or a streamed cache copy.
- **No React re-render may reach the native viewer.** `PdfManager.onAfterUpdateTransaction` posts `drawPdf()` (a full reload) after every prop update, and the `Pdf` JS class re-creates its `style` array on each render. `PdfView` is `React.memo` with a comparator on `fileUri`, `password`, `horizontal` only; callbacks go through refs; page jumps use the `setPage` command, never the `page` prop (which is the initial/resume page).
- **Night/sepia = RN `filter` style on a non-collapsable wrapper View.** RN 0.86 `BaseViewManager.LayerEffectsHelper` applies color-matrix-only filters (`invert`, `hueRotate`, `sepia`) as a `Paint` `ColorFilter` on a hardware layer on every API level (only non-matrix filters need API 31). `react-native-pdf` does not expose AndroidPdfViewer's `nightMode`. Night = `[{ invert: 1 }, { hueRotate: '180deg' }]` (keeps photo hues), sepia = `[{ sepia: 0.7 }]`. Verified visually in Task 10.
- **Share / print / open-with are implemented in `pdf-native`, not `expo-sharing`/`expo-print`.** `expo-sharing.shareAsync` takes a local file URL only and `expo-print` prints HTML/URLs it re-renders; we need `content://` sources (SAF, intent rows), any file size (print streams the bytes, `PAGE_COUNT_UNKNOWN`), and excluding our own activity from the open-with chooser. The module declares its own `PdfNativeFileProvider` (a `FileProvider` subclass — `react-native-blob-util` already declares `androidx.core.content.FileProvider`, and two providers with the same class name clash in manifest merging).
- **Incoming intents:** `VIEW` (cold and warm) reaches JS through RN `Linking` (RN `IntentModule`/`ReactHostImpl` forward `ACTION_VIEW` data URIs) and Expo Router's `redirectSystemPath({ path, initial })` (checked in `expo-router/build/link/linking.js` and `getLinkingConfig.js`); `app/+native-intent.tsx` rewrites `content://`/`file://` to `/open?uri=…`. `SEND` is not a `Linking` URL, so `pdf-native` reads it (`takeIncomingPdf()` for the launch intent, `OnNewIntent` → event `onIncomingPdf` when warm) and JS navigates to `/open`. `expo-sharing`'s receive feature is experimental and does not cover `VIEW`, so it is not used. Intent filters come from `app.config.ts` `android.intentFilters` (Expo's built-in plugin; `data.mimeType` is in the SDK 57 config schema) — `VIEW` and `SEND` with `mimeType: application/pdf` (no scheme ⇒ Android implies `content:` and `file:`).
- **Intent rows:** `/open` resolves the URI (`resolveIncomingPdf`, which also takes a persistable read grant when the provider offers one), then `registerIncoming`: if a row with that exact URI exists it is reused unchanged (a scanned file opened via "Open with" stays a `scan` row); otherwise it is inserted with source `'intent'`, `folder ''`, `parentUri ''`. Intent rows show in All and Recent, never in Folders. A cold "Open with" skips onboarding and the permission gate; back from that reader returns to the sending app.
- **Permission mode `'none'`:** the Files tab stays gated (M2 behaviour). Home shows the access card **plus** a "Recent" row of files opened in the app whose source is `'intent'` or `'output'` (rows that need no storage access), so an "Open with" file can be reopened.
- **Reader priority over list thumbnails:** reader thumbnails use a new `ReaderThumbnails` class with its own `Mutex` and one cached open `PdfRenderer` per document, so they never queue behind the Files-list thumbnail jobs (M2 `Thumbnails.kt` keeps its process-wide lock). Framework `PdfRenderer` serialises individual native calls internally, so two instances are safe.
- **Password flow:** no pre-prompt from `files.isEncrypted` (that flag comes from `PdfRenderer`, which also rejects owner-password-only PDFs that pdfium opens without a password). The viewer error `"Password required or incorrect password."` with an empty password ⇒ "Password required"; with a non-empty one ⇒ "Wrong password. Try again." Print is blocked for files that needed a password (Android's print spooler renders with `PdfRenderer`); decrypt arrives with T-08 (M7).
- V-04 is a horizontal thumbnail **strip** (no separate grid). Bookmarks toggle per page (label `''`, shown as "Page N"). Last page is saved with a 500 ms trailing debounce plus a flush on unmount and on app background.
- Fixtures: `__fixtures__/outline.pdf` (committed). The 50 MB scanned fixture is **generated locally** by `npm run fixtures:large` into gitignored `__fixtures__/large/` (too big for git) and pushed to the emulator in Task 10.
- `react-native-blob-util`'s manifest adds `ACCESS_WIFI_STATE` and `DOWNLOAD_WITHOUT_NOTIFICATION`; both go into `android.blockedPermissions` (offline app). `WAKE_LOCK`/`INTERNET` are left (needed later by WorkManager/ads).

## Review Focus

1. Huge files (the 50 MB scanned fixture, 100 MB files, 50 MB `content://` shares) → no OOM and no ANR: the viewer only receives `file://` paths, `content://` is stream-copied off the UI thread, thumbnails are lazy and ≤ 240 px wide. Tests: Task 2 (`PdfView` refuses a non-`file://` uri), Task 3 (`ReaderCache` pruning keeps ≤ 3 copies / 300 MB), Task 10 (device, 50 MB fixture opens and scrolls).
2. Wrong passwords → each wrong entry shows "Wrong password. Try again." in the same dialog, no automatic retry loop, Cancel leaves the reader, the correct password opens the file, the password is never persisted. Tests: Task 6 (`readerReducer`), Task 7 (screen flow with `protected.pdf` semantics), Task 10 (device, "secret" and a wrong password).
3. `content://` grant gone (warm intent's grant ended, intent row reopened after a restart, SAF grant revoked) → "PDF Toolkit can't open this file anymore…", row kept, no crash. Tests: Task 6 (`openReaderFile` maps `ERR_PERMISSION_DENIED`), Task 7 (row not dropped), Task 9 (`openIncomingPdf` → `permission`).
4. App backgrounded, killed or the activity recreated mid-read (theme/locale change, process death) → the current page is saved before the process can die and the next open resumes there. Tests: Task 6 (`createLastPageSaver.flush`), Task 7 (AppState `background` flushes, unmount flushes, resume clamps to page count).
5. File deleted, moved or its SD card removed while open or between list and open → deleted: "This file no longer exists" and the row disappears; unmounted volume / I/O error: message, row stays; share/print of a deleted file: message, no crash. Tests: Task 7 (open errors), Task 8 (action errors).
