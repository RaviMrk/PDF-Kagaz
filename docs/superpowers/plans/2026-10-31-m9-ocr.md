# Milestone 9 — OCR (Make searchable) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The "Make searchable (OCR)" tool (T-13) goes live. It reads printed text in the scanned pages of a PDF on the phone with Google ML Kit text recognition (Latin script, bundled model), and saves a new PDF that looks the same but has an invisible, searchable and selectable text layer.

**Architecture:** One native op, `ocrPdf(fileUri, jobId)`, runs the whole job in Kotlin like Compress. For each page, PdfBox checks whether the page already has text (it is then skipped). Otherwise PdfRenderer renders the page as seen (300 DPI, pixel-capped), ML Kit returns word boxes in bitmap pixels, `OcrGeometry` maps each box to user space (CropBox and `/Rotate` aware, reusing `StampGeometry.placeOnPage`), and `OcrTextLayer` appends the words as render-mode-3 (invisible) Helvetica text scaled to each box. The page renderer and ML Kit sit behind a `PageRecognizer` seam, so the PdfBox side is tested in Robolectric with a fake recognizer. JS adds an `ocr` runner, two new failure kinds, a result summary and an options screen. Everything else (staging, passwords, workspace, publish, background notice, cancel) is the existing tool framework.

**Tech Stack:** Expo SDK 57, TypeScript strict, Jest; Kotlin + `com.tom-roush:pdfbox-android:2.0.27.0` (existing), Android `PdfRenderer`. **New:** `com.google.mlkit:text-recognition:16.0.1` (bundled Latin model, no Play services or network needed; latest per the ML Kit release notes, 2024-08-07, the release that added 16 KB page-size support).

**Spec:** `docs/REQUIREMENTS.md` §3.3 T-13 ("Make scanned PDF searchable; English first, then Devanagari", P2), §2 v1.2 row (OCR only; text search V-11, annotations V-12 and mr/hi stay out), §4 (memory, app size ≤ 40 MB, privacy: no uploads), §9 item 8 (OCR part only), §10.2 (16 KB check). No separate design doc: the user asked (2026-10-31) to skip the design questions and build OCR "on-device only". Rulings made without a design doc are provisional and listed in the final report.

## Global Constraints

- Android only; minSdk 24, targetSdk 36. Routes only in root `app/`. Screens never import pdf-lib or `modules/pdf-native`; they use `src/services/**` (ESLint boundaries and `eslintImports.test.ts` stay green).
- `npm run typecheck`, `npm run lint`, `npm test` and `npm run format:check` pass at the end of every task. Native changes also pass `cd android && ./gradlew :pdf-native:testDebugUnitTest :app:compileDebugKotlin` after `npx expo prebuild --platform android --clean`, with `export JAVA_HOME=~/.gradle/jdks/eclipse_adoptium-17-aarch64-os_x.2/jdk-17.0.20.1+1/Contents/Home` and `export ANDROID_HOME=~/Library/Android/sdk`.
- **On-device only.** No network call, no upload, no Play-services model download. The only new dependency is `com.google.mlkit:text-recognition:16.0.1`, added only in `modules/pdf-native/android/build.gradle`. No new manifest permission.
- **Reliability:** the op reads the staged (decrypted) workspace input and writes `out-ocr.pdf` in the same job workspace through a part file (`PdfBoxSupport.saveTo`); the runner publishes it with `publishToolOutput`. The original is never written; no "Replace original".
- **Limits:** `TOOL_ENGINE.ocr = 'native'` (so `NATIVE_CAPS`). Page render: `OCR_DPI = 300`, sized by `RenderSizing.sizeFor` (so ≤ `RENDER_MAX_PIXELS = 12_582_912`). PdfBox opens through `PdfBoxSupport.open` (mixed memory, temp dir `pdfbox-ocr` in the workspace, deleted afterwards).
- **Privacy in logs:** Kotlin never logs or puts into an exception message any recognized text, file name or path.
- All user-facing strings in `src/i18n/en.json`, exact copy given in the tasks. Plurals use i18next `_one` / `_other`. Touch targets ≥ 48 dp; every pressable has an `accessibilityLabel`.
- Commit after each task; messages end with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Ads stay off; don't touch `src/services/ads/**`. No foldable checks (use Pixel_10a and Rangoli_LowEnd_API34).

**Decisions this plan makes (the spec leaves them open):**
- **Bundled model, Latin only.** Works offline on first use and without Play services. Devanagari is out of scope.
- **Invisible text:** PDF text render mode 3, font `PDType1Font.HELVETICA` (Standard 14, not embedded), WinAnsi. A word's text is NFC-normalised; each character not in WinAnsi is replaced by its NFD base letter when that is WinAnsi (é stays é, ł → `?`, ș → s), else `?`. A word that is blank afterwards is dropped.
- **Word fit:** font size = box height in points; horizontal scaling `Tz = 100 × boxWidth / naturalWidth`; baseline raised by `DESCENT_FRACTION = 0.2` × font size above the box bottom (in text space). Word boxes only (ML Kit elements); element angles are ignored.
- **Pages that already have text are skipped** (no option): a page counts as having text when `PDFTextStripper` finds at least `MIN_TEXT_CHARS = 20` non-whitespace characters on it. So the tool never doubles up text.
- **Outcomes:** every page skipped → failure `alreadySearchable` (nothing saved). Pages OCR'd but zero words found in total → failure `noTextFound` (nothing saved). Otherwise one new PDF named `"{{name}} searchable"`, and the result screen summarises pages with text added / skipped / with no text found.
- **Progress:** one unit per page plus one for the save. Cancel is checked before and after each page's recognition (ML Kit's own call is not interruptible; a page takes about a second).

## Review Focus

1. **Rotated or cropped scanned pages** (`/Rotate 90`, a CropBox offset from the MediaBox). Expected: selecting a word in a viewer highlights roughly where the word is printed, and search finds it. Tests: Task 1 `OcrGeometryTest` (rotation 0/90/180/270 and an offset CropBox vectors), `OcrTextLayerTest.rotatedPageExtracts`; Task 5 device check on page 2 of `scanned-text.pdf`.
2. **A PDF that is already text** (a normal digital PDF, or a mixed one). Expected: text pages are left untouched; an all-text PDF says "This PDF already has searchable text" and saves nothing. Tests: Task 1 `PdfOcrTest.allTextSkipsAndWritesNothing`, `PdfOcrTest.mixedSkipsTextPage` (recognizer never called for the text page); Task 3 `ocr runner` failure test.
3. **Non-English Latin text and odd characters** (accents, `ł`, `ß`, curly quotes, emoji in ML Kit output). Expected: no crash, accents kept where WinAnsi has them, others become a base letter or `?`. Tests: Task 1 `OcrTextTest`.
4. **Long or large scans on a low-RAM phone** (`__fixtures__/large/scanned-50mb.pdf`, 300 DPI A3 pages). Expected: no OOM; one page bitmap at a time, recycled; cancel from the notification stops within one page. Tests: Task 1 `PdfOcrTest.cancelLeavesNoOutput`; Task 5 run on Rangoli_LowEnd_API34.
5. **A locked input** (`protected.pdf`). Expected: the password prompt shows, OCR runs on the decrypted copy, the result notes the new file has no password. Tests: Task 3 runner test with `passwords`; existing framework tests stay green.
